Refresh Logout and PDF Fix

Trip Planner (Musafir) frontend · branch trip_planner.AI · 2026-09-24 · manually verified by the user

1. Original Request

Found during the Phase 7 manual check of the localhost frontend: "save as pdf option is not visible and after refreshing page its directly logged out". Decision: always show Save as PDF and Delete, and relabel Print as "Save as PDF".

2. Implementation Summary

Refresh logout (bug). AuthProvider read the token from localStorage correctly, but only passed it to the API client inside a useEffect. React runs child effects before parent effects, so after a refresh the page's first query went out with no Authorization header. The backend returned 401, and the client's 401 handler called logout(), which cleared the token. The fix sets the client token synchronously: in the state initializer and inside login/logout.

PDF button. The button was labeled "Print" and only appeared once the trip had at least one activity, as the spec said. Delete was hidden the same way, so an empty trip couldn't be deleted. Both buttons now always show, and Print is renamed "Save as PDF". An empty trip's PDF lists each day as "(no activities planned)", which the PDF code already handled.

6. Exact Page / URL to Test

7. Step-by-Step Manual Verification

  1. Restart npm run dev (or rely on hot reload) and open http://localhost:5173.
  2. Log in.
  3. Press F5 on the trips list.
  4. Create a new trip and don't add any activities.
  5. Press F5 on the trip page.
  6. Click Save as PDF.
  7. Add an activity to Day 1, then click Save as PDF again.
  8. Click Delete and confirm.
  9. Click Logout, then press F5.

8. Expected Results

  1. The login page (or the trips list if you're already logged in).
  2. You're redirected to the trips list.
  3. You stay logged in and your trips reload.
  4. The trip page shows the Save as PDF and Delete buttons straight away.
  5. You're still logged in and the same trip shows.
  6. A <destination>.pdf downloads, with each day marked "(no activities planned)".
  7. The PDF lists the activity under Day 1.
  8. You return to the trips list and the trip is gone.
  9. You stay on the login page, because logout clears the stored token.

9. Known Issues and Limitations

  • The user confirmed the browser checks on localhost (2026-09-24).
  • JWTs expire after the backend's jwt_expiry_minutes. After that, a refresh correctly sends you back to the login page.
  • The deployed Vercel frontend still can't call the HTTP-only ALB API until CloudFront (HTTPS) is unblocked.
  • The 2 existing lint warnings (AuthContext.tsx fast refresh, useDraftPersistence.ts setState in an effect) weren't addressed.
