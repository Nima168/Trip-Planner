0. What is this app? (start here)

Musafir Travels helps you plan a trip. You can either chat with an AI assistant ("Solo trip to Goa from 1 to 3 October") or fill in a short form. Either way you give four details: destination, start date, end date and trip type (solo, couple, family, group of friends). The app then creates one page per day of the trip, where you add activities. At the end you can save the itinerary as a PDF.

The app has three parts that live in different places and talk to each other over the internet:

1. The frontend (what you see). A React website hosted on Vercel. It runs in your browser: buttons, chat, forms.
2. The backend (the brain). A Python FastAPI server running on AWS. It checks passwords, saves trips, and asks the AI for help.
3. The database (the memory). PostgreSQL on AWS RDS. It stores users, trips, days and activities.
+ The AI. Groq runs the openai/gpt-oss-120b model. The backend sends it the chat, and it returns the four trip details in a fixed format.

0.1 Words you'll see (glossary)

API
The set of web addresses the frontend calls to ask the backend for things, e.g. POST /api/v1/trips ("create a trip").
HTTP / HTTPS
The language browsers and servers speak. HTTPS is the encrypted version (the padlock). Browsers refuse to let an HTTPS page call a plain-HTTP address; this is called mixed content.
JWT (token)
A signed "wristband" the backend gives you when you log in. The frontend sends it with every request to prove who you are.
CORS
A browser safety rule: a page on one website may only read answers from another website if that website explicitly allows it.
Container / Docker
A packaged, ready-to-run copy of the backend with everything it needs. Built once, run anywhere.
ECR
AWS's storage for container images, a bit like a library of backend versions (one per commit).
ECS Fargate
AWS service that runs our container without us managing servers.
ALB (load balancer)
The front door on AWS. It receives web requests and forwards them to the running backend.
RDS
AWS's managed PostgreSQL database, kept in a private network the internet can't reach.
Secrets Manager
A vault on AWS for passwords and keys (database URL, JWT secret, Groq key). They're injected into the backend at startup, never written in code.
CloudFront
AWS's global "edge" network. We want it to give the API an HTTPS address. It's blocked until AWS verifies the account (see 2.4).
Terraform
"Infrastructure as code": text files that describe all the AWS resources, so they can be created or changed with one command.
CI/CD
Continuous Integration / Continuous Deployment. On every push, GitHub Actions tests the code and, if it passes, deploys it automatically.
Migration (Alembic)
A script that creates or updates database tables to match the code.
Rate limit / 429
"Too many requests, please wait." Groq's free tier allows about 5 AI turns per minute; the app then shows a countdown.
Proxy / rewrite
Vercel forwards /api/... calls to AWS behind the scenes, so the browser only ever talks HTTPS to Vercel.

1. Original Request

Goal (from specs_new/goal-spec.md): travelers scatter trip plans across notes apps and chats. Give them one place to create a trip (destination, dates, trip type), plan it day by day, and export it as a PDF. It should be a responsive web app with sign-up and log-in, built by one person in about two weekends.

Approved AI enhancement: describe the trip in English or Hinglish, review the details the AI extracted, then confirm. Manual entry must always remain available.

How the requests grew over the project:

  1. v1: a simple trip planner (FastAPI + React), with tests and CI, deployed on Render and Vercel.
  2. v2: replace v1 completely with the new specs (specs_new/), adding accounts, AI, and AWS infrastructure.
  3. Run on AWS with Terraform, deploy automatically from GitHub, and verify everything by hand.
  4. Switch the AI to Groq only (openai/gpt-oss-120b).
  5. A friendly "please wait" message when the AI rate limit is hit.
  6. An attractive, user-friendly UI using the two project photos.
  7. No trips in the past: show an error if the start or end date is before today.
  8. Go live on Vercel, make it the final version, clean up, and write this report (including CloudFront).

2.4 CloudFront: status and how to finish it

Why we need it

Vercel serves the site over HTTPS. Our AWS load balancer only speaks HTTP, because it has no certificate: AWS can't issue one for the *.elb.amazonaws.com address. Browsers block an HTTPS page from calling HTTP. CloudFront would put an HTTPS address, https://xxxx.cloudfront.net, in front of the load balancer.

Current status

Blocked by AWS. Creating the distribution returned 403 AccessDenied: Your account must be verified before you can add new CloudFront resources (request ID e6f897ad-a7d2-402a-bfb2-5504772c6758). The Terraform code is ready in infra/modules/cdn, but it's commented out in infra/environments/prod/main.tf.

The temporary workaround now in use

frontend/vercel.json forwards every /api/* call to the load balancer, with caching turned off because the data is private to each user. frontend/.env.production points the app at /api/v1 on its own address. The browser only ever talks HTTPS to Vercel.

Security caveat: the hop from Vercel to AWS is still plain HTTP, so passwords and login tokens aren't encrypted on that stretch. That's fine for a demo or course project; switch to CloudFront before real users arrive.

How to finish it once AWS verifies the account

  1. Confirm: in the AWS console, the Support Center case about account verification shows as resolved (include the request ID above in the case).
  2. Turn the code back on. In infra/environments/prod/main.tf, uncomment the module "cdn" block. In outputs.tf, uncomment cloudfront_domain_name and change api_base_url to: 
    value = "https://${module.cdn.cloudfront_domain_name}/api/v1"
  3. Apply (the Groq key must always be set when applying): 
    cd infra/environments/prod
$env:TF_VAR_ai_api_key = "gsk_..."
terraform plan     # expect: 1 to add (the CloudFront distribution)
terraform apply
terraform output api_base_url   # e.g. https://d1234abcd.cloudfront.net/api/v1
    Creating a distribution takes about 5–15 minutes.
  4. Test it: curl https://<id>.cloudfront.net/health should return {"status":"ok"}.
  5. Point the frontend at it: set VITE_API_BASE_URL in frontend/.env.production to the CloudFront URL, and delete the /api/:path* rewrite (and its header block) from frontend/vercel.json. Keep the /(.*) → /index.html rewrite. CORS already allows https://musafir-trip-planner.vercel.app.
  6. Update GitHub: in the repository's Actions variables, set API_BASE_URL to the CloudFront URL (the deploy health check uses it).
  7. Push to trip_planner.AI. Vercel and AWS both redeploy. Then run the manual checks in section 7 again.
  8. Optional hardening: let only CloudFront reach the ALB, using the managed prefix list com.amazonaws.global.cloudfront.origin-facing in the ALB security group.

7. Step-by-Step Manual Verification

  1. Open https://musafir-trip-planner.vercel.app and click Create an account. Pick a username and password.
  2. Press F5 (refresh) on the "Your trips" page.
  3. Click Plan a trip, click the suggestion chip "Solo trip to Goa from 1 to 3 October", then press Send.
  4. In a new chat (use Discard draft first), send "Goa trip from 1 to 3 September 2026, alone".
  5. Switch to Enter details manually, enter a past From date (e.g. 10-09-2026), then change it to next month.
  6. Complete a trip and click Create trip.
  7. On the trip page, open Day 1, add an activity, edit it, then delete it.
  8. Click Save as PDF.
  9. Send 6 or more chat messages quickly (or use two tabs).
  10. Open the site on your phone.
  11. Click Log out, then press F5.

9. Known Issues and Limitations

  • No CloudFront yet: the Vercel-to-AWS hop is plain HTTP (section 2.4). Fine for a demo; not for real users.
  • Groq free tier: about 5 AI turns per minute across all users, plus daily limits. After that, users see the countdown or are offered manual entry. Upgrading Groq raises the limits.
  • AI rate limit per server process: the app's own limit (10 per user per minute) is kept in memory, so it resets on restart and isn't shared if ECS runs several copies.
  • RDS backups: 1 day, the AWS free-plan maximum. Raise to 7 after upgrading the account plan.
  • Terraform gotcha: every terraform apply needs $env:TF_VAR_ai_api_key set, or the stored Groq key is overwritten with an empty value. Limiting an apply to one resource (-target) avoids this when the key isn't touched.
  • Fixed test dates: some backend tests use 2027 dates and will fail once those dates are in the past. The new tests use relative dates.
  • Photos: the source images are small (500×281 and 900×600), so they look slightly soft on large screens.
  • Emoji for trip types depend on the device's emoji font.

Appendix A. Retiring the v1 app

Two old services still run. Nothing in v2 depends on them, and the v1 data was deliberately discarded.

1. Render (old backend, trip-planner-4tgv.onrender.com)

  1. Go to dashboard.render.com and open the web service behind trip-planner-4tgv.
  2. Settings → Suspend Web Service. This is reversible, and a good safety step first.
  3. After a few days, if nothing is needed: Settings → Delete Web Service (you'll type the name to confirm). This permanently removes it and its SQLite data.
  4. If v1 had an OPENWEATHER_API_KEY on Render, revoke or rotate it at openweathermap.org.

2. Vercel (old frontend project, trip-planner-two-beta.vercel.app)

  1. Go to vercel.com and open the project named trip-planner. Not musafir-trip-planner.
  2. Settings → General, scroll to the bottom, then Delete Project and type the name to confirm.
  3. It currently serves the v2 app (it builds from master), so nobody loses anything. Check that musafir-trip-planner.vercel.app still works afterwards.
