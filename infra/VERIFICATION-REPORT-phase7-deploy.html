7. Step-by-Step Manual Verification

  1. Open the health URL in a browser.
  2. In frontend/, set VITE_API_BASE_URL=http://musafir-alb-1646923822.us-east-1.elb.amazonaws.com/api/v1 (in .env.local) and run npm run dev.
  3. Open http://localhost:5173 and sign up with a new username.
  4. Log out, then log in again.
  5. Create a trip with a destination, dates and trip type.
  6. Add an activity to day 1, edit it, then delete it.
  7. Export the trip as a PDF.
  8. Open the AI chat and send a message.
  9. Delete the trip.

9. Known Issues and Limitations

  • No HTTPS: CloudFront is blocked until AWS verifies the account, so the API runs over plain HTTP and passwords and tokens are unencrypted in transit. The Vercel (HTTPS) frontend can't call this API because browsers block mixed content, so only localhost works for now.
  • AI disabled: ai_enabled=false. To enable it, set it to true and apply with -var ai_api_key=…, then deploy again.
  • No RDS backups: backup_retention_days=0.
  • Test data: test user phase7check_1790252346 remains in the database (there's no delete-user endpoint). Its trip was deleted.
  • CI warnings (not failures): Node 20 deprecation on actions/*@v4, and 2 frontend lint warnings (useDraftPersistence.ts:82 setState in an effect, AuthContext.tsx:81 fast refresh).
  • Git still shows plan.txt as untracked. It isn't committed.
