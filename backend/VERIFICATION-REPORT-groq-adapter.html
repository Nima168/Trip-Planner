Groq AI Provider

Trip Planner (Musafir) · branch trip_planner.AI · 2026-09-24 · not committed, not applied

1. Original Request

Build a Groq adapter for the AI trip-draft feature using GPT-OSS 120B. Then: "keep it Groq only, not Anthropic. Wherever API calling is mentioned, say Groq is used, not Anthropic. Also tell me where to set the API key."

2. Implementation Summary

  • GroqAdapter calls Groq's OpenAI-compatible chat API with openai/gpt-oss-120b. It forces a single tool call, RESULT_TOOL_SCHEMA (unchanged), and parses the tool call's JSON arguments into the same draft shape the endpoint already validates.
  • Settings: max_completion_tokens=4096 and reasoning_effort="low", because this is a reasoning model and its reasoning tokens count toward the limit. max_retries=0, with the existing 20-second timeout.
  • Error mapping: a timeout returns 504. Connection errors, 429 and other status codes return 503. Groq's 400 tool_use_failed, a bad tool call, JSON that doesn't parse, and a response truncated by the length limit all return 502.
  • Anthropic is removed: AnthropicAdapter, the anthropic import and the anthropic==1.6.0 dependency are gone. AI_PROVIDER only accepts "groq", so a leftover anthropic value stops the app at startup.
  • Terraform: the prod configuration now has ai_provider (restricted to groq) and ai_model variables, passed to the ECS module; the module defaults are now Groq.
  • Specs, CLAUDE.md, PROGRESS.md and the example env files now describe Groq only.

Update: follow-up turn failing ("returned something unexpected")

Symptom (found by the user in local testing): after "I would like to visit goa on next monday alone", the follow-up "yes its on october 3rd" returned 502.

Cause: with forced tool calling, gpt-oss-120b on Groq intermittently produced a malformed tool call (400 tool_use_failed). Replaying that turn failed about 1 time in 4.

Fix: GroqAdapter now asks for the result with Groq's strict JSON-schema structured output (constrained decoding) instead of a tool call. RESULT_SCHEMA closes every object, as strict mode requires. The prompt says to return one JSON object (prompt v2). Every AI failure is now logged with a sanitized reason (field paths and error types, no user text).

Evidence: 6 of 6 live runs of the user's conversation succeeded (about 1.7 s per turn, previously about 3.5 s), and a call through the running local backend returned 200. pytest: 60 passed, including a test that the schema meets strict-mode rules.

Also found: the Groq free tier allows 8,000 tokens per minute. At about 1,400 tokens per turn, that's roughly 5 AI turns per minute; beyond that users see 503 "AI provider unavailable".

7. Step-by-Step Manual Verification

  1. Create a key at https://console.groq.com/keys.
  2. Local: in backend/.env, set AI_API_KEY=gsk_... and AI_ENABLED=true, then restart uvicorn.
  3. Open /trips/new and type "Solo trip to Goa from Oct 1 to Oct 3".
  4. Type a vague message, e.g. "somewhere warm next month".
  5. AWS: in PowerShell, $env:TF_VAR_ai_api_key = "gsk_...", set ai_enabled = true in terraform.tfvars, then run terraform apply and deploy.

8. Expected Results

  2. The backend starts with no settings error.
  3. The draft fills in destination, dates and type, and a reply asks for confirmation.
  4. The assistant asks a clarifying question instead of guessing.
  5. /ai/trip-draft returns 200 with a draft, not 503.

9. Known Issues and Limitations

  • Deploy order matters: the live ECS task definition still sets AI_PROVIDER=anthropic. Apply Terraform before pushing this code; otherwise the new container fails at startup and the deploy's health check fails.
  • Every later terraform apply needs TF_VAR_ai_api_key set once AI is enabled. Without it, the stored key is overwritten with an empty value.
  • backend/.env has a valid Groq key (checked: gsk_ prefix, 56 characters, live calls succeed). AI_ENABLED is still false there.
  • Only 2 live Groq calls so far (both good, about 3 s each). Reliability of the forced tool call across the full range of chat scenarios hasn't been measured.
  • Groq's free tier has per-minute and per-day limits; hitting them returns 503 "AI provider unavailable".
  • The 1,024-token cap in the original spec became 4,096 for the reasoning model; recorded in AI-spec.md.
