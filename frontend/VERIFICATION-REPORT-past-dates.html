No Past Trip Dates

Musafir Travels · branch trip_planner.AI · 2026-09-25 · local only (not committed or deployed)

1. Original Request

"In the trip details, check if the start and end date are in the past; if so, show an error message that the start date should be in the future."

2. Implementation Summary

  • Rule: a trip must start today or later (the user's local date). Today counts as valid, so same-day trips still work.
  • Trip details panel: a past start or end date gets a red border and "Start/End date can't be in the past — choose today or a later date." It doesn't count toward "N of 4 ready", Create trip is disabled, and the date pickers won't offer past days (min=today).
  • Chat: typing "yes" to confirm is also blocked while a date is in the past. The AI prompt (v3) no longer fills in past dates; it explains and asks for a new one.
  • Backend: POST /trips returns 400 start_date cannot be in the past, which the app turns into the same friendly message. The server allows one day of slack because it doesn't know the user's timezone (the browser enforces the exact rule).

9. Known Issues and Limitations

  • "Today" follows the user's device clock and timezone. The server only rejects dates more than a day before today in UTC, so someone who deliberately changes their clock could still create yesterday's trip.
  • Existing trips with past dates (e.g. the demo "Hampi" trip) are untouched; only creating a trip is checked. The existing backend tests use fixed 2027 dates, which will start failing after 2027.
