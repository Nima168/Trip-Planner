UI Redesign Report

Musafir Travels · branch trip_planner.AI · 2026-09-25 · local only (not committed or deployed)

1. Original Request

"1. When the 5 turns per minute gets exceeded, show an error message like 'wait for a few minutes' etc. 2. I want an attractive UI/UX; you can use the two images in the trip-planner project folder. Make it user-friendly."

2. Implementation Summary

Rate-limit message

  • Backend: Groq's 429 now becomes AIProviderRateLimited, and the API returns 429 + Retry-After (before, it returned a vague 503). The wait time comes from Groq's retry-after header, or else its "try again in 1m30.5s" text, or else 30 seconds.
  • CORS fix: expose_headers=["Retry-After"]. Without it, browsers hide the header from JavaScript, so the frontend could never read how long to wait. This also applied to the existing per-user 429.
  • Frontend: ApiError.retryAfterSeconds, plus a useCountdown hook. The chat shows a friendly notice with a live countdown and progress bar, keeps the chat and draft, disables Send, then shows "Ready! … Send again". Waits over 2 minutes (a daily quota) say so and offer "Enter details manually". Other AI errors now get a Retry button that resends the last message.

UI/UX redesign

  • Look: a warm "golden hour" theme built from your two photos (converted to public/images/hero-clouds.jpg and hero-road.jpg). Terracotta primary colour (white text meets WCAG AA, 4.9:1), Fraunces headings with Fira Sans body, shared button, card and input classes, and inline SVG icons (no new dependencies).
  • Login and sign-up: split screen with the clouds photo and feature highlights; show/hide password toggle; plain-language errors.
  • Header: sticky, with a logo, "My trips", "Plan a trip", an avatar and log out.
  • Home: road-photo banner "Hi {name}, where to next?", and trip cards in a grid sorted upcoming first, with "Starts in N days / Happening now / Completed" badges, length and type. Loading skeletons and a friendly empty state.
  • New trip: segmented mode switch; chat with an assistant avatar, suggestion chips, typing dots and auto-scroll; details panel with an "N of 4 ready" progress bar and ticks.
  • Trip page: photo banner with the facts and prominent Save as PDF / Delete; days as a numbered timeline with activity previews, Expand all, and icon edit/delete (Escape cancels an edit).

9. Known Issues and Limitations

  • Image resolution: the source photos are small (road 500×281, clouds 900×600), so they look soft on large or high-DPI screens. Dark overlays hide most of this; higher-resolution versions would look sharper.
  • Trip-type emoji depend on the operating system's emoji font. On Windows some show as two figures (e.g. family).
  • The AI's closing line says "Please review these details" rather than the spec's exact "Shall I create this trip?…". That's prompt wording, not UI; it wasn't changed here.
  • The original public/image_back_ui.jfif and image_front_ui.avif are still in public/ (unused; they could be removed).
  • Dev servers: the old Vite needed a restart to pick up the new Tailwind config, and uvicorn --reload left an orphaned worker serving old code (documented in CLAUDE.md). Both now run without auto-reload in Claude's session.
  • Nothing is committed or deployed. Production still runs the pre-Groq code with AI off.
